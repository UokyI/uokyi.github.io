Privacy Policy

Last updated: October 22, 2026

LAN Drop (known in Chinese as 局域网快传) ("we", "our", or "this extension") is a browser extension for Microsoft Edge that lets you send files from your phone to your computer. You scan a QR code with your phone, and the file is transferred peer-to-peer to your computer over a WebRTC DataChannel. This privacy policy explains what data we collect and how we use it.

Data Collection

We do NOT collect any personal data.

This extension has no account system, no analytics, no advertising, and no tracking of any kind. It does not read, modify, or track the web pages you visit.

How the Extension Works

The extension runs a receiver panel on your computer. When you start receiving, it generates a QR code containing a random session code and the address of the upload page. Your phone opens that page and sends the selected files to your computer over a WebRTC DataChannel — a direct, peer-to-peer connection. The file content itself is never uploaded to any server.

Data Storage

The extension uses Chrome's local storage (chrome.storage.local) to save your signaling server settings, including:

  • Selected signaling server preset
  • Server host, port, path, and key (for self-hosted PeerServer)
  • WebSocket URL (for a self-hosted signal.ashx)
  • Phone upload page URL

These settings remain strictly on your local device and are never uploaded or shared. The extension also uses chrome.storage.session to remember the panel tab id so it can focus the existing panel instead of opening a new one; this value is cleared when the tab closes.

Files you receive are temporarily buffered in the browser's Origin Private File System (OPFS), then saved to your normal Downloads folder. Temporary copies are cleaned up after the download completes, and any leftovers are removed the next time you open the panel.

Permissions

  • storage - Used solely to save your signaling settings and panel tab id locally.
  • downloads - Used solely to save received files to your Downloads folder.

The extension requests no host_permissions. It cannot access or read web content in the background.

Third-Party Services

To establish a WebRTC connection, the extension and the phone page must exchange connection details through a signaling server. The extension ships with the following options, and you can switch between them in the panel:

  • zhong.tech (default) - A WebSocket signaling endpoint self-hosted by the project author and currently provided free of charge, without any availability guarantee. The server keeps no access logs and does not store signaling content or files.
  • PeerJS Cloud - The free public service at 0.peerjs.com, operated by a third party.
  • Self-hosted PeerServer - A server you deploy yourself.
  • Self-hosted signal.ashx - A WebSocket service you deploy yourself.

WebRTC also uses a public STUN server (stun.l.google.com) to discover network addresses. No file content is sent to the signaling or STUN servers. The extension does not use any third-party analytics or tracking tools.

What the Signaling Server Can See

To connect two devices, the signaling server relays the session code, the SDP session description, and ICE candidates (which may include local or public IP addresses of your devices). It cannot see the content of your files, because files travel directly between the two devices. For sensitive scenarios, please use a self-hosted signaling server.

Children's Privacy

This extension does not knowingly collect any data from children or any other users.
